`createSession` turns a `LernoDocument` into a running session. It owns the cursor, grades answers
through the registry, keeps the score, and notifies subscribers. Persistence, telemetry, and flow
resolution arrive from host adapters, so the same session works in a browser, in a test, or on a
server.

## Usage

```ts
import { questionSet, createSession } from '@medu/lerno';

const document = questionSet('quiz-1', { title: 'Quadratic equations' }, [
  {
    kind: 'solution-steps',
    prompt: 'Solve x² − 4 = 0.',
    steps: [
      { id: 's1', prompt: 'Factor it', accepted: ['(x-2)(x+2)'] },
      { id: 's2', prompt: 'Write the roots', accepted: ['2,-2', '-2,2'] },
    ],
  },
]);

const session = createSession(document);

session.getState().cursor;          // 'q1': questionSet names nodes q1, q2, ...
const { outcome } = session.answer('q1', { steps: ['(x-2)(x+2)', 'wrong'] });
outcome.status;                     // 'partial'
session.score();                    // { earned: 1, max: 2, ratio: 0.5, passed: null }

session.next();                     // null: the document ends here
```

## Determinism

`answer` is a pure function of the response and the document: the same response always produces the
same `GradeOutcome`, and nothing reads the clock except `answeredAt`. That is what lets a test
assert on a session without mocking time.

`score().passed` stays `null` until every graded question has an answer, so a partially attempted
quiz never reports a pass or a fail.
