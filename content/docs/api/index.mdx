This section is not a set of guides; it is a **member-level reference**. Everything exported by
`@medu/lerno` is listed under one of three headings (classes, types, and functions) and every
detail page follows the same order: constructor, properties, methods.

Guides answer "how do I build this"; these pages answer "which members exist". Conceptual background
lives in [Core concepts](/docs/concepts), working examples live in [Disciplines](/docs/disciplines).

## Subpath imports

The root re-exports content, runtime, scene graph, and discipline helpers. React views are a separate
subpath, so a surface that only draws does not pay for the content schema:

| Entry | Contains | zod |
| --- | --- | --- |
| `@medu/lerno` | Content, runtime, scene graph, helpers | yes |
| `@medu/lerno/core` | Scene graph, observables, geometry, tween, sim loop | **no** |
| `@medu/lerno/session` | `createSession` and the session types | yes |
| `@medu/lerno/content` | Document schema, validation, presets | yes |
| `@medu/lerno/grading` | Graders, `defineQuestion`, response schemas | yes |
| `@medu/lerno/extensions` | `createLerno`, `createHost`, `defineExtension` | yes (default graders) |
| `@medu/lerno/remotion` | React/SVG views (`MathCanvas`, `CoordinateSystemView`, `FunctionPlotView`) | yes (React) |

```ts
import { Node, CircleNode, Property } from '@medu/lerno/core';
import { createSession } from '@medu/lerno/session';
```

Any other path is blocked by the `exports` map, so an import cannot reach `dist/` internals by
accident.

## How to read it

Member names, types, and `@param` and `@returns` entries match the TypeScript source exactly.
Descriptions of members come from the English source; the prose of each page is written per locale.
